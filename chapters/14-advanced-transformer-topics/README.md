# Chapter 14: Advanced Transformer Topics

A trained Transformer never writes a sentence by itself. At every step it only assigns a probability to each token in its vocabulary, and a separate search procedure decides what actually gets written. Chapter 6 built and trained the original encoder-decoder Transformer; this chapter takes that finished model and asks what it takes to use it well. The answers have concrete consequences: the search procedure changes the quality of the output, the parameter and FLOP counts set how much memory and compute a model needs, and the choice of which stacks to keep decides whether a model translates, classifies, or turns text into vectors for search. The chapter turns the model's distributions into outputs with greedy decoding and beam search, counts parameters and compute from a configuration, surveys the encoder-decoder and encoder-only families that grew from the original design, and uses encoders as embedding models. Along the way we implement beam search, check the cost formulas against PyTorch, and build a small semantic search engine.

## Suggested code labs

1. **Greedy decoding and beam search.** Using the small encoder-decoder trained in the fourth code lab of Chapter 6 (date-format conversion or digit sorting), implement greedy decoding and beam search with the length penalty of Wu et al. (2016). Check that beam size 1 reproduces greedy decoding, then compare exact-match accuracy and decoding speed on a held-out set for several beam sizes and values of $`\alpha`$.
2. **Count parameters and FLOPs.** Write functions that compute a Transformer's parameter count and forward-pass FLOPs from its configuration. Check the parameter count against `nn.Transformer` and the FLOPs against PyTorch's FLOP counter, then plot how the share of compute spent on attention grows with sequence length.
3. **Semantic search with an encoder.** Extract BERT's last-layer vectors for an ambiguous word such as "bank" in a dozen sentences and check that they cluster by sense. Then embed a small document collection (a few dozen short texts on several topics) with a sentence embedding model such as `all-MiniLM-L6-v2`, answer queries by cosine similarity, and compare the results with keyword overlap and with mean-pooled vectors from plain BERT. Write ten queries with hand-marked relevant documents and report recall@3 for each method, and cluster the collection with k-means.

## Key takeaways

- A trained model gives a distribution over the next token; decoding turns it into an output. Greedy decoding is fast, beam search keeps several hypotheses, and a length penalty keeps beam search from favoring short outputs.
- A Transformer's size and cost follow from its configuration: about $`12d^2`$ parameters per encoder block and $`16d^2`$ per decoder block plus $`Vd`$ for embeddings, about 2 FLOPs per parameter per token in a forward pass, and attention terms that grow quadratically with sequence length.
- Transformer families differ mainly in which stacks they keep and what they are trained to predict: encoder-decoder models (T5, BART) map sequences to sequences, and encoder-only models (BERT, ViT) produce representations of their input.
- An encoder's output vectors are contextual embeddings; pooled and trained contrastively, they turn any text into a vector for semantic search, clustering, and classification with few labels.

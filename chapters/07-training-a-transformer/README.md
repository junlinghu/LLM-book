# Chapter 7: Training a Transformer

A trained Transformer never writes a sentence by itself. At every step it only assigns a probability to each token in its vocabulary, and a separate search procedure decides what actually gets written. Chapter 6 built the parts of the original Transformer; this chapter assembles them into the full encoder-decoder model, trains it, and then asks what it takes to use the finished model well. The answers have concrete consequences: the search procedure changes the quality of the output, the parameter and FLOP counts set how much memory and compute a model needs, and the choice of which stacks to keep decides whether a model translates, classifies, or turns text into vectors for search. The chapter builds the encoder and decoder blocks, trains the full model on sequence-to-sequence data with teacher forcing, label smoothing, and a warmup schedule, turns the model's distributions into outputs with greedy decoding and beam search, counts parameters and compute from a configuration, surveys the encoder-decoder and encoder-only families that grew from the original design, and uses encoders as embedding models. Along the way we train a small encoder-decoder on a toy task, implement beam search, check the cost formulas against PyTorch, and build a small semantic search engine.

## Suggested code labs

1. **Encoder and decoder blocks with mask tests.** Implement multi-head attention with reshapes (no loop over heads), then an encoder block and a decoder block (masked self-attention, cross-attention, FFN, residuals, and LayerNorm). Write tests that change a future target token and assert that earlier decoder outputs are unchanged, and that change a padded source position and assert that no output changes. Copy your weights into `nn.TransformerEncoderLayer` and `nn.TransformerDecoderLayer` and confirm the outputs match, and check each block's parameter count against $`12d^2`$ and $`16d^2`$ plus biases and normalization parameters.
2. **Train a small encoder-decoder Transformer on a toy seq2seq task.** Build the full model from your blocks and train it on date-format conversion (for example "March 7, 2019" to "2019-03-07") or on sorting short sequences of digits, using teacher forcing, label smoothing, and the warmup schedule. Check the initial loss against $`\ln V`$ and that the model can overfit a single batch. Then plot training and validation loss, and measure teacher-forced token accuracy on a held-out set, with and without label smoothing.
3. **Greedy decoding and beam search.** Using the small encoder-decoder trained in Lab 2 (date-format conversion or digit sorting), implement greedy decoding and beam search with the length penalty of Wu et al. (2016). Check that beam size 1 reproduces greedy decoding, then compare exact-match accuracy and decoding speed on a held-out set for several beam sizes and values of $`\alpha`$.
4. **Count parameters and FLOPs.** Write functions that compute a Transformer's parameter count and forward-pass FLOPs from its configuration. Check the parameter count against `nn.Transformer` and the FLOPs against PyTorch's FLOP counter, then plot how the share of compute spent on attention grows with sequence length.
5. **Semantic search with an encoder.** Extract BERT's last-layer vectors for an ambiguous word such as "bank" in a dozen sentences and check that they cluster by sense. Then embed a small document collection (a few dozen short texts on several topics) with a sentence embedding model such as `all-MiniLM-L6-v2`, answer queries by cosine similarity, and compare the results with keyword overlap and with mean-pooled vectors from plain BERT. Write ten queries with hand-marked relevant documents and report recall@3 for each method, and cluster the collection with k-means.

## Key takeaways

- The encoder block is self-attention plus an FFN; the decoder block adds masked self-attention and cross-attention; each sublayer is wrapped in a residual connection with layer normalization.
- Training uses teacher forcing, so every target position is trained in one parallel pass, together with label smoothing and a warmup learning-rate schedule.
- A trained model gives a distribution over the next token; decoding turns it into an output. Greedy decoding is fast, beam search keeps several hypotheses, and a length penalty keeps beam search from favoring short outputs.
- A Transformer's size and cost follow from its configuration: about $`12d^2`$ parameters per encoder block and $`16d^2`$ per decoder block plus $`Vd`$ for embeddings, about 2 FLOPs per parameter per token in a forward pass, and attention terms that grow quadratically with sequence length.
- Transformer families differ mainly in which stacks they keep and what they are trained to predict: encoder-decoder models (T5, BART) map sequences to sequences, and encoder-only models (BERT, ViT) produce representations of their input.
- An encoder's output vectors are contextual embeddings; pooled and trained contrastively, they turn any text into a vector for semantic search, clustering, and classification with few labels.
